# Overview

**North** is a desktop workspace for infrastructure — not just an SSH launcher.

Organize clients, environments, remote connections and accesses (database credentials or portal logins) in one place. Remote sessions run **inside the app**: embedded terminal, desktop and file transfer.

## What you get

- Clear hierarchy: Client → Environment → Group → items
- In-app sessions without relying on external clients
- Credentials in the local vault (`safeStorage` / OS keychain)
- Group workflows for repeatable actions (deploy, restart, health-check)
- Command Palette and shortcuts to go from inventory to session in seconds
- Local profile (display name and optional e-mail) in **Settings** — this machine only, shown in the sidebar chip
- App font in **Settings → App font** — the interface family (Inter by default) applies to the window, menus, and forms. The monospace family applies to the terminal, code editors, the log panel, hosts, ports, and shortcuts, and still includes Ubuntu Mono, Fira Code, Source Code Pro, Cascadia, Hack, Inconsolata, Roboto Mono, Space Mono, and Noto Sans Mono, besides the earlier ones. Size scales the interface and the terminal. Ligatures start off and apply only to monospace text

## Workspaces

The button at the top right, next to VPN, shows which workspace you're in. **My workspace** stays on this computer, in the local database and the system vault. Use the **+** next to **Organizations**, enter your company's North Server address and click **Sign in with Microsoft**: your browser opens your company's sign-in page (Entra ID) and, once you sign in, you come back to North already inside the organization. North never sees your Microsoft password. Test servers also accept sign-in by e-mail. In an organization, clients, environments, groups, connections and tags live on the server and are shared with the team; favorites are yours only. Nothing syncs between workspaces. You can already connect from an organization. Each connection's password is stored encrypted on the server, and North fetches it only when opening the session, keeping no copy on this computer. Every time a password is read (to connect or to paste into the terminal), the server records who read it and why. In an organization, each person sees only what an admin shared with them: a client, an environment, a group or a single connection, given to them directly or to a **team** they are in. Someone given one connection sees only that connection, with the path to it, and nothing else in the group. Each grant has one of three roles: **Admin** does everything and creates clients; **Editor** creates, edits and deletes what is inside the project; **Viewer** sees and connects, but cannot edit, reveal or paste the password. Buttons you cannot use are hidden. If the tree is empty, ask an organization admin for access. Admins open the **Admin panel** from the workspace selector (or at the server address followed by `/admin`) to add people, build teams, give and remove access (from a whole client down to one connection), see everything each person can reach, disable people who left and see the audit. A team can follow a Microsoft Entra group: people in the group join the team when they sign in to North, and leave it when they leave the group. All of this applies right away: what the team changes shows up in your North without reloading, and anyone who loses access to a connection has its session closed. A disabled person leaves the organization and goes back to My workspace. Databases and logins (web portals) live in the organization too, with the same rules as connections: you can share a single access, and a Viewer connects to the database or opens the portal without seeing the password. Private keys stay per computer. So do VPN logins: the organization keeps only the gateway, and each person signs in with their own username and password (see the VPNs chapter). Workflows live in the organization too: each person runs them on their own computer, with their own VPN, and the update history shows who ran them (see the Workflows chapter). API collections inside an organization come in the next versions. In **Settings**, the **You in …** section shows your role and which teams you are in; sharing a client already shares everything inside it. In the admin panel, check several items at once (or **Check all clients**) and click **Share**. To bring what you already have into the organization (or take it back), right-click a client, environment, group or connection and use **Copy to workspace…**: pick the workspace and where to put it, and check **Copy passwords** to take them along. The copy is new and independent, so changing one doesn't change the other. Passwords copied to the organization go encrypted to the server, and each password read from the organization is audited. Databases, logins, tags and the client's VPN come along. Workflows and group variables go along too. API collections are left out, and North tells you; of an OpenVPN only the address goes, and each person uses their own `.ovpn`. To bring several clients at once, open the organization and use **Settings → Inventory → Copy from My workspace…**: tick the clients and click Copy. Spreadsheet (CSV) import also works inside an organization, with servers, databases and logins. To leave, open the selector and pick **Leave this organization**.
